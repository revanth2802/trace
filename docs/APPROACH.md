# Trace: the review record is the product

Trace organizes a tax workpaper around evidence, uncertainty and accountability. The home screen answers: what does the return say, what needs attention, and what prevents filing? A figure opens a calculation and evidence drawer. Sources open simulated documents built from the packet’s actual printed_content, with page, field, read text and confidence. Missing extracted text is explicitly marked rather than presented as verified truth. The document index also shows reverse destinations and records exclusions.

The source packet remains unchanged. Return versions are immutable engine outputs. Reviewer actions live in a separate persisted workpaper: adjustments, verifications, review resolutions, questions and answers, judgments with authority, attachments, assignments, time entries, approvals, filing snapshots and audit events. An adjustment records original/effective values, actor, timestamp, reason and estimated federal/state effects. Dependent verifications and signatures reopen after a numeric change. The original filing snapshot survives an amendment.

The data model has two Postgres tables. `workpapers` stores the household review aggregate and monotonic revision. `access_logs` independently records unmasked payload access. Every write checks the revision using an atomic compare-and-swap; stale writes are rejected and the client refreshes. Polling provides shared updates every 15 seconds. The role switcher uses a server-set HttpOnly cookie for case-study personas; the server applies permissions and redacts restricted responses. Reviewer access is configured at the deployment layer. Demo personas are intentionally selectable and are not production staff authentication.

Material UI 9 supplies shared theme, buttons, fields, tables, status chips, dialogs, drawers and feedback. The official App Router cache integration streams Emotion styles into the document head, with a CSS layer that permits the project’s layout styles to retain the existing visual design. Dialogs add keyboard focus trapping and Escape handling. React/TypeScript runs on standard Next.js with Postgres persistence and Vercel deployment configuration. There is no extraction model or tax engine. Deterministic independent checks find duplicate evidence, the wrong FX year, missing brokerage detail and disagreements with agency records. Engine diagnostics are labeled separately. Supplied engine scenarios compare alternate outcomes without modifying the base return. Adjustment effects use packet marginal rates and remain estimates: the UI does not silently claim downstream engine figures have been recomputed.

Tradeoffs: a single aggregate makes consistency and immutable checkpoints easy to inspect for one household; a production firm system would normalize engagements, events, attachments and review subjects, paginate server-side, use real staff identities and independent client authorization, store files in object storage, add push updates, and run authoritative recalculation. The prototype supports simulated filing and downloadable JSON records; it does not transmit returns, implement legal electronic signatures, or schedule destructive retention jobs.

AI usage: Codex assisted packet inspection, interface implementation, deterministic checks, tests and documentation. No runtime external AI service receives taxpayer data. The inventoried packet and application checks provide evidence; model confidence does not constitute verification.
